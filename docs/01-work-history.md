# 작업 단계와 변경 내역

로컬 개발 작업을 단계별로 정리합니다. 실제 업무 자료, 조직 식별 정보와 비공개 디자인 원본의 내용은 기록하지 않습니다.

## 1. 요구사항 및 구현 방향

- 갤럭시탭용 Flutter Android 앱으로 구현 방향을 정했습니다.
- 로그인 없이 종합 현황으로 진입하도록 구성했습니다.
- 인터넷과 내부 서버 없이 저장·조회·추론하는 구조를 설계했습니다.
- 화면 디자인을 바탕으로 공통 메뉴, 카드, 표, 입력 화면을 구성했습니다.
- 가로·세로 화면과 좁은 창에서도 사용할 수 있도록 배치했습니다.

## 2. 기본 업무 화면 구현

차량 현황과 상세, 정비 분석과 기록, 정비·운용 입력, 점검, 분석 이력, 질문 기록을 연결했습니다. 검색·필터·정렬과 상세 조회를 구현하고, 정비 기록은 12건씩 나누어 표시해 대량 목록의 렌더링 부담을 줄였습니다.

질문 화면은 질문 저장과 관련 정비 기록 조회를 지원합니다. 자유로운 답변을 생성하는 언어 모델은 아직 연결하지 않았습니다.

## 3. 로컬 저장과 카메라 연결

SQLite에 차량, 정비, 운용, 점검, 질문과 예측 이력을 저장하도록 구현했습니다. 실제 카메라 미리보기·촬영 경로와 앱 내부 원본 저장, 수동 점검 메모 및 세션 조회를 연결했습니다.

폰트·화면 자산·앱 초기 목업·모델을 앱에 포함했습니다. Android 인터넷·네트워크 상태 권한을 제거했고 앱 데이터의 자동 백업을 비활성화했습니다. 촬영 기능은 구현했지만 실기기 확인은 남아 있습니다.

## 4. 합성 학습 데이터 v2 제작

실제 기록을 복사하지 않고 가상 차량 500대의 월별 운용과 정비 이력을 생성했습니다. 예측 표본 24,000건을 만들고 차량 단위 학습·검증·시험 분할을 적용했습니다.

초기에는 연식·주행량·과거 정비로 사건 확률을 계산하고 난수로 다음 달 수리 발생 여부를 정했습니다. AUC 0.630, F1 0.287이었고, 운행의 연속성과 다음 사건을 예측할 수 있는 관측 패턴이 약하다는 점을 확인했습니다.

## 5. 모델 학습과 앱 추론 연결

- 정비 발생 예측: L2 로지스틱 회귀.
- 정비 문장 분류: 문자 2·3그램 다항 나이브 베이즈.
- PC에서 학습한 매개변수를 JSON으로 내보내고 Dart로 추론.
- 정비·운용 저장 후 관련 차량의 특성·예측·화면 갱신과 이력 저장.
- 사용자 확인 후 분류 제안을 적용하도록 구성.

## 6. 합성 시나리오 v3 개선 및 재학습

정기 예방정비, 정비 지연, 운행량 증가, 반복 수리, 저운행, 고운행의 6가지 시나리오를 도입했습니다. 운행량이 다음 달로 이어지고 가상 마모 상태가 정비 전후에 변화하도록 개선했습니다.

관측 가능한 유류 소모 변화와 정비 이력으로 다음 달을 추정하게 했으며 내부 마모와 시나리오 이름은 특성에서 제외했습니다. 미래 기간을 학습에서 제외하고 미학습 차량의 미래 기록을 별도로 평가했습니다.

새 과제의 전체 시험 AUC는 0.884, F1은 0.515였습니다. 입력 오차와 문장 누락 시험도 수행해 취약한 조건을 기록했습니다. 실제 자료에서 성능이 향상됐다는 의미는 아닙니다.

## 7. 갱신 안정성과 최종 검증

동시·연속 입력, 저장 후 화면 갱신, 예측 불가 상태 전환, 재실행 후 데이터 유지, 이전 목업 교체 시 사용자 입력 보호를 검증했습니다. Python과 Dart의 추론 값·특성 계산도 비교했습니다.

자동 테스트 15개 통과, 정적 분석, 개발용 APK 빌드를 완료했습니다. APK에 최신 모델과 목업이 포함됐는지 바이트 단위로 확인했습니다.

## 8. 기록 관리와 백업·복원 구현

정비 수정·삭제와 최근 운용 기록 수정·삭제를 연결하고, 변경 전후 이력을 보관합니다. 중복 정비와 잘못된 날짜, 앞뒤 운용 누적값 범위를 검사합니다.

사진·분석·질문·변경 이력을 포함하는 파일 백업과 확인 후 전체 복원을 구현했습니다. 원래 사진 경로를 포함하지 않고 새 내부 경로에 저장합니다. DB 교체와 예측 재계산을 한 트랜잭션으로 묶고 실패 시 DB·화면·사진을 보호하도록 구성했습니다.

이 단계에서 자동 테스트 23개, 정적 분석 및 Android APK 빌드를 통과했습니다. Android 파일 선택·저장 연동의 실기기 동작은 확인이 남아 있습니다.

## 9. 전체 운용 기록·변경 이력 조회와 분석 보류 사유

운용 관리의 최근 12건 제한을 없애고 전체 기록을 12건씩 넘겨 조회하도록 보완했습니다. 차량을 바꾸면 첫 페이지로 이동하며 삭제 뒤 페이지 범위를 조정합니다.

수정·삭제 이력은 DB에서 12건씩 최신순으로 조회하고 변경 항목의 전후 값 또는 삭제 전 내용을 화면에서 확인합니다. 같은 시각에 저장한 이력도 저장 순서대로 정렬합니다.

운용 기록 없음, 월별 증분 부족, 잘못된 입력, 주행 증가에 대응하는 시간·유류 증가량 없음 등의 분석 보류 사유를 표시·저장합니다. 입력 보정 뒤 예측 재개를 확인했으며 학습 모델의 가중치는 유지했습니다.

전체 자동 테스트 26개, 화면 이미지 비교, 정적 분석과 개발용 APK 빌드를 통과했습니다. 과거 운용 기록의 수정 화면 진입, 변경 전후 비교, 이력 페이지 순서와 분석 보류·회복 검사를 추가했습니다.

# 앱 구현과 로컬 구성

## 기술 구성

| 역할 | 기술 | 적용 내용 |
| --- | --- | --- |
| 앱·화면 | Flutter / Dart | Android 태블릿, 한국어, 반응형 배치 |
| 상태·이동 | Riverpod / go_router | 저장 상태 공유와 화면 이동 |
| 저장 | Drift / SQLite | 내부 테이블, 검색·집계·마이그레이션 |
| 촬영·파일 | Camera / path_provider | 미리보기, 원본과 앱 내부 저장 |
| 화면 자산 | flutter_svg / 번들 폰트 | 외부 다운로드 없는 화면 구성 |
| 학습 | Python / NumPy | PC에서 합성 모델 학습 |
| 추론 | Dart / JSON | 태블릿에서 매개변수 계산 |

검증 개발 환경은 Flutter 3.47.7, Dart 3.13.5입니다. Android 최소 API는 24, 대상 API는 36입니다. 전 기종에 대한 검증을 의미하지 않습니다.

## 화면별 기능

| 화면 | 동작 |
| --- | --- |
| 종합 현황 | 차량 수, 상태 구간, 정비 요약, 우선 조회 차량 |
| 차량 현황·상세 | 검색·필터·정렬, 누적값과 관련 이력 |
| 정비 분석 | 기간·계통·월별 정비 건수와 비용 |
| 정비 기록·상세 | 검색·필터·정렬, 12건 단위 페이지와 상세 |
| 데이터 입력 | 정비·운용 저장, 누적값 감소 검사, 분류 제안 |
| 점검 | 카메라·촬영, 수동 메모, 원본·세션 저장 |
| 분석 이력 | 예측 결과, 모델 버전과 갱신 사유 |
| 질문 기록 | 질문 저장과 관련 정비 이력 조회 |

상태 구간은 목업 추정치를 화면에 나눈 것으로 실제 차량 안전 판정 구간이 아닙니다.

## 저장 구조

차량·정비·운용·점검·질문·예측 이력은 SQLite에 보관합니다. 사진은 앱 내부 파일로 저장하고 점검 기록과 연결합니다. 서버 동기화와 여러 기기 간 자동 공유는 없습니다.

앱 삭제·데이터 초기화 시 기록과 사진이 삭제될 수 있습니다. 파일 내보내기·백업·복원은 아직 구현하지 않았습니다.

## 입력에서 화면 갱신까지

1. 입력을 검증하고 누적값 감소를 거부합니다.
2. 내부 DB에 기록을 저장합니다.
3. 해당 차량의 과거 기록에서 14개 특성을 다시 계산합니다.
4. 번들 모델로 추론합니다.
5. 확률·특성·모델 버전·갱신 사유를 저장합니다.
6. 상태 변경을 알리고 화면을 갱신합니다.

사용자 입력으로 자동 재학습하지 않습니다. 모델 매개변수 해시가 바뀌면 예측을 다시 계산하고, 같은 모델·날짜·특성이면 이력을 중복 추가하지 않습니다.

읽기·갱신을 순서대로 처리하며 기록 ID에 128비트 난수를 사용합니다. 같은 시각의 운용 기록은 저장 순서로 최신을 결정합니다. 정보 부족으로 계산할 수 없으면 미분석 상태를 저장해 이전 확률이 다시 나타나지 않게 했습니다.

## 월중 입력과 목업 교체

학습은 월말 관측을 기준으로 하며 월중 입력은 임시 추정으로 표시합니다. 부분월 정확도는 별도 검증 대상입니다.

이전 목업 교체 시 정비·운용 사용자 입력이 없는 차량의 합성 이력만 바꿉니다. 입력이 있는 차량은 전체 이력을 보존해 서로 다른 가상 이력이 섞이지 않게 합니다. 보존된 이전 이력의 성능은 새 시험 점수로 입증되지 않았습니다.

## 네트워크 범위

운영 앱은 로그인, 원격 API, 클라우드 동기화, 모델 다운로드를 사용하지 않습니다. 폰트·이미지·목업·모델을 번들로 포함합니다. 개발 PC에서 SDK·패키지를 준비하는 과정에는 네트워크가 필요할 수 있습니다.

인터넷 권한을 제거한 개발 APK는 네트워크 기반 디버깅에 제한이 있어 재빌드·USB 설치로 확인합니다. 이 설정만으로 별도 보안 인증이나 감사를 완료한 것은 아닙니다.

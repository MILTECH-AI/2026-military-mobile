# 로컬 기록 관리와 백업·복원

2026-10-14 추가: AI 정비지원에 등록한 문서 원문·출처 위치·차종·부품 정보와 정비 주기·교환 기준도 사진 포함 백업에 함께 보관합니다. 질문에 지정한 표준부품명도 유지합니다. 이 자료가 없는 기존 백업은 빈 정비지원 자료로 복원됩니다.

v0.2.0 추가: 등록 차량과 초기 운용 계기, 정비 기록에 연결한 점검 ID·교환 완료 여부·당시 계기도 보존합니다. 사진 경로를 정비 기록에 복사하지 않고 점검 ID로 연결하므로 복원된 사진 위치에서도 같은 기록을 다시 열 수 있습니다. 교환 완료 기록의 수정·삭제 후 다음 주기는 남아 있는 완료 기록과 등록 기준에서 다시 계산합니다. 기존 백업의 완료 정보가 없는 정비 기록은 교환 여부 미확인으로 유지합니다.

교환 여부는 수정 화면과 상세 화면에서 미확인·교환 없음·교환 완료로 구분합니다. 교환 여부를 건드리지 않고 가격 등 다른 필드만 수정해 저장하면 원래 null/false/true가 유지됩니다. 이를 DB 재조회와 화면 재진입까지 포함한 테스트로 확인합니다. 보류 원인 기록은 정비지원·정비계획·종합현황의 ‘확인하기’에서 수정할 수 있습니다.

정비 자료 반입은 데이터 관리의 로컬 파일 선택기를 사용합니다. 부품 개념·품번 후보·문서 근거·일반/가혹 주기·검토 대기 실적을 검증하고, 미리보기 확인 후 하나의 트랜잭션으로 저장합니다. 검토 대기 실적은 Maintenance 형식을 유지하되 활성 maintenance 행으로 승격하지 않아 차량 생성·이력 집계·ML 입력에 섞이지 않습니다. 작성 경위와 차량 연결이 확인되기 전의 상태를 백업에도 유지합니다.

확장 자료는 maintenance_support 메타데이터 버전 2에 보존하며 버전 1 자료도 읽습니다. 일반·가혹 기준과 선택 이력, 원문 파일·쪽·해시, 검토 대기 상태는 재실행과 백업·복원 후 유지됩니다. 구버전 앱이 확장 메타데이터를 읽는 전방 호환성은 보장하지 않습니다. 원문 해시의 존재·형식 검사와 실제 원본 대조는 다른 검증이며, 앱이 반입 문서의 진위를 자동 인증하는 것은 아닙니다.

## 추가한 기능

- 정비 기록 상세에서 수정과 삭제를 실행합니다. 삭제 전 대상 기록을 확인하는 창을 표시합니다.
- 데이터 관리 화면에서 선택 차량의 전체 기간 운용 기록을 12건씩 넘겨 조회하고 수정·삭제합니다.
- 수정·삭제 전후 내용을 변경 이력으로 보관하고 관련 차량의 집계와 예측을 갱신합니다. 이력도 12건씩 조회하며 항목을 눌러 변경 전후 값을 비교합니다.
- 기록과 점검 사진을 `.mbackup` 파일 하나로 저장하고 시스템 파일 선택기를 통해 복원합니다.

질문·점검·분석·변경 이력도 백업에 포함합니다. 모델 파일 자체는 앱에 포함된 것을 사용하며 백업으로 학습 모델을 교체하지 않습니다.

## 입력과 수정 규칙

정비 날짜는 존재하는 날짜여야 하며 미래 또는 출고연도 이전 날짜를 거부합니다. 차량·날짜·부속·내용·가격·계통·정비 구분이 동일한 정비 기록의 중복 등록도 거부합니다.

운용 수정은 원래 기록 시각을 유지합니다. 거리·시간·유류 누적값은 앞뒤 기록 사이 범위여야 합니다. 최신 기록을 삭제하면 남은 최신 기록으로 차량 누적값을 다시 계산하며, 운용 기록이 모두 없으면 누적값은 0, 예측은 미분석으로 처리합니다.

변경 이력은 수정·삭제 내용을 추적하기 위한 저장 자료입니다. 사용자 인증 이력이나 변경 내용의 자동 되돌리기 기능은 아닙니다.

## 분석 보류와 입력 보정

운용 기록 없음, 월별 증분 계산에 필요한 기록 부족·주행 증가량 없음, 잘못된 기록 시각·누적값, 주행 증가에 대응하는 시간·유류 증가량 없음 등의 조건에서는 현재 예측을 표시하지 않습니다. 차량 상세에 보류 사유를 표시하고 분석 저장 자료에도 사유를 남깁니다.

기록을 수정하면 관련 차량을 다시 계산하며 유효한 입력이 확보되면 예측을 재개합니다. 과거의 유효한 분석 이력은 유지합니다. 보류 조건은 입력 품질 검사이며 실제 고장 여부를 판별하는 기준이 아닙니다. 기존 숫자 모델의 가중치나 학습 성능 지표를 변경하지 않았습니다.

## 백업 저장

1. 메뉴에서 데이터 관리를 엽니다.
2. 백업 파일 저장을 누릅니다.
3. 시스템 파일 선택기에서 기기 또는 USB의 로컬 저장 위치를 선택합니다.

기록과 사진은 압축된 JSON 형식으로 보관합니다. 백업은 암호화되지 않았으므로 보관·공개 범위를 사용자가 결정해야 합니다. 앱은 백업을 서버로 전송하지 않습니다.

사진의 원래 절대 경로는 백업에 저장하지 않습니다. 기록 ID와 이미지 데이터를 연결하며 복원 시 앱 내부에 새 경로를 만듭니다. 원본 사진이 없거나 크기 제한을 넘으면 사진을 누락한 백업을 만들지 않고 오류를 표시합니다.

## 복원

1. 백업 파일 복원을 누르고 로컬 파일을 선택합니다.
2. 파일 형식·버전·참조·고유 ID·누적값·사진을 검사합니다.
3. 확인창에서 생성일, 기록 수와 사진 수를 검토합니다.
4. 교체하여 복원을 누르면 현재 DB를 해당 백업으로 교체합니다.

취소하면 현재 기록을 유지합니다. 복원은 병합이 아니므로 현재 기록을 먼저 백업할 수 있습니다. 삭제된 기록이 초기 목업으로 다시 주입되지 않도록 초기화 메타데이터도 보존합니다.

새 사진을 준비한 후 DB 교체와 예측 재계산을 하나의 트랜잭션에서 실행합니다. 실패하면 기존 DB와 화면 상태를 유지하고 준비한 사진을 정리합니다. 기존 사진 원본은 복원 중 자동 삭제하지 않습니다. 성공 뒤의 참조되지 않는 이전 사진 정리는 아직 구현하지 않았습니다.

## 크기와 호환성

| 항목 | 현재 제한 |
| --- | --- |
| 압축 파일 | 64MB |
| 압축 해제 내용 | 128MB |
| 사진 1개 | 10MB |
| 테이블별 기록 | 100,000건 |
| 지원 형식 | 백업 버전 1, DB 스키마 4 |

원래 기기 경로를 복원 경로로 사용하지 않습니다. 사진 ID를 검증해 경로 이탈을 막고, 가져온 임시 파일은 앱 캐시 범위에서 정리합니다. 내용 검사는 파일 서명·발신자 인증을 의미하지 않습니다.

## 검증과 남은 확인

수정·삭제와 예측 갱신, 앞뒤 누적값 제한, 중복·잘못된 날짜, 사진 포함 백업 왕복, 동시 백업·입력, 재실행 유지, 손상·참조 오류·경로 이탈 입력 거부를 자동 테스트했습니다.

DB 삽입 또는 예측 재계산 실패를 주입해 기존 기록·사진·화면 상태가 유지되는지도 검사했습니다. 화면 테스트에서는 수정·삭제와 백업 저장·복원 확인·취소를 검증합니다. Android 파일 선택·저장 코드는 APK 빌드로 확인했으며 실제 USB 파일 선택과 권한 동작은 갤럭시탭에서 검증해야 합니다.

## 로컬 임베딩 묶음과 확인 정보

데이터 관리 맨 아래 기기 사양·모델 단계 설정에서 `.mrag`를 시스템 파일 선택기로 반입합니다. 앱은 모델을 내려받지 않습니다. 파일 구성·크기·SHA-256을 확인하고 앱 내부 전용 경로에 설치하며 근거 등록은 별도로 확인받아 기존 반입 트랜잭션을 사용합니다. 설치 후 실제 차량·지침 적용조건을 확인해야 해당 근거가 검색 범위에 들어갑니다. 시험용 묶음은 정비실적·실제 차량 식별자를 제외하며 산출물은 private, `.mrag` 확장자는 gitignore로 보호합니다.

일반 기록 백업은 새 개념 확인시각도 보존하지만 별도 모델·벡터 파일을 포함하지 않습니다. 복원 후 모델이 없으면 키워드 검색을 유지하고 모델을 다시 반입할 수 있습니다. 현재 등록 원문·적용 문서와 색인이 달라지면 이전 벡터를 조용히 재사용하지 않습니다.

이름이 일치해도 부품 개념은 자동 확정하지 않습니다. 기존 확인시각 없는 연결은 후보로 다루며, 개념 선택과 확인을 거친 기록만 확인 정보로 저장합니다. 다른 필드 수정은 확인시각을 유지하고 실제 품명 수정은 해제합니다. 입력란의 커서 이동은 품명 변경으로 처리하지 않습니다.

## 분류 파일럿 자료와 계측

세 번째 모듈의 공식 명칭은 **규칙 기반 잔여 정비거리 + 정비기록 분류**입니다. 과거 측정 원본은 변경하지 않고 새 명칭·현재 평가 보고서를 연결한 측정 색인을 별도로 둡니다. 실제 시계열 정비이력 확보 후 예측 모델 확장은 기존 자료 반입·출처 확인·기준시각 규칙을 유지하는 별도 단계입니다.

실제 정비 원문·AI 초안 라벨·분할 감사·학습된 ONNX와 `.msystem`·평가 질문·측정 결과는 모두 private에 보관합니다. `.msystem`도 전역 무시 패턴에 포함합니다. 독립 라벨링 배포본은 보관만 하며 재평가·외부 전송하지 않습니다. 전체 흐름 시험은 가상 ID와 공개 사진으로 수행하고 실제 정비실적·식별자를 APK에 포함하지 않습니다.

파일럿 모델은 일반 정비 기록 백업과 분리한 로컬 파일 반입입니다. 반입하지 않았거나 실행이 실패해도 계통을 수동 선택하고 정비를 저장할 수 있습니다. 모델 점수나 AI 초안은 검증된 실차 이력·고장 확률로 승격하지 않습니다.

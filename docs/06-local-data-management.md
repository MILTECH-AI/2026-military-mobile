# 로컬 기록 관리와 백업·복원

## 추가한 기능

- 정비 기록 상세에서 수정과 삭제를 실행합니다. 삭제 전 대상 기록을 확인하는 창을 표시합니다.
- 데이터 관리 화면에서 선택 차량의 최근 운용 기록 12건을 조회하고 수정·삭제합니다.
- 수정·삭제 전후 내용을 변경 이력으로 보관하고 관련 차량의 집계와 예측을 갱신합니다.
- 기록과 점검 사진을 `.mbackup` 파일 하나로 저장하고 시스템 파일 선택기를 통해 복원합니다.

질문·점검·분석·변경 이력도 백업에 포함합니다. 모델 파일 자체는 앱에 포함된 것을 사용하며 백업으로 학습 모델을 교체하지 않습니다.

## 입력과 수정 규칙

정비 날짜는 존재하는 날짜여야 하며 미래 또는 출고연도 이전 날짜를 거부합니다. 차량·날짜·부속·내용·가격·계통·정비 구분이 동일한 정비 기록의 중복 등록도 거부합니다.

운용 수정은 원래 기록 시각을 유지합니다. 거리·시간·유류 누적값은 앞뒤 기록 사이 범위여야 합니다. 최신 기록을 삭제하면 남은 최신 기록으로 차량 누적값을 다시 계산하며, 운용 기록이 모두 없으면 누적값은 0, 예측은 미분석으로 처리합니다.

변경 이력은 수정·삭제 내용을 추적하기 위한 저장 자료입니다. 사용자 인증 이력이나 변경 내용의 자동 되돌리기 기능은 아닙니다.

## 백업 저장

1. 메뉴에서 데이터 관리를 엽니다.
2. 백업 파일 저장을 누릅니다.
3. 시스템 파일 선택기에서 기기 또는 USB의 로컬 저장 위치를 선택합니다.

기록과 사진은 압축된 JSON 형식으로 보관합니다. 백업은 암호화되지 않았으므로 보관·공개 범위를 사용자가 결정해야 합니다. 앱은 백업을 서버로 전송하지 않습니다.

사진의 원래 절대 경로는 백업에 저장하지 않습니다. 기록 ID와 이미지 데이터를 연결하며 복원 시 앱 내부에 새 경로를 만듭니다. 원본 사진이 없거나 크기 제한을 넘으면 사진을 누락한 백업을 만들지 않고 오류를 표시합니다.

## 복원

1. 백업 파일 복원을 누르고 로컬 파일을 선택합니다.
2. 파일 형식·버전·참조·고유 ID·누적값·사진을 검사합니다.
3. 확인창에서 생성일, 기록 수와 사진 수를 검토합니다.
4. 교체하여 복원을 누르면 현재 DB를 해당 백업으로 교체합니다.

취소하면 현재 기록을 유지합니다. 복원은 병합이 아니므로 현재 기록을 먼저 백업할 수 있습니다. 삭제된 기록이 초기 목업으로 다시 주입되지 않도록 초기화 메타데이터도 보존합니다.

새 사진을 준비한 후 DB 교체와 예측 재계산을 하나의 트랜잭션에서 실행합니다. 실패하면 기존 DB와 화면 상태를 유지하고 준비한 사진을 정리합니다. 기존 사진 원본은 복원 중 자동 삭제하지 않습니다. 성공 뒤의 참조되지 않는 이전 사진 정리는 아직 구현하지 않았습니다.

## 크기와 호환성

| 항목 | 현재 제한 |
| --- | --- |
| 압축 파일 | 64MB |
| 압축 해제 내용 | 128MB |
| 사진 1개 | 10MB |
| 테이블별 기록 | 100,000건 |
| 지원 형식 | 백업 버전 1, DB 스키마 4 |

원래 기기 경로를 복원 경로로 사용하지 않습니다. 사진 ID를 검증해 경로 이탈을 막고, 가져온 임시 파일은 앱 캐시 범위에서 정리합니다. 내용 검사는 파일 서명·발신자 인증을 의미하지 않습니다.

## 검증과 남은 확인

수정·삭제와 예측 갱신, 앞뒤 누적값 제한, 중복·잘못된 날짜, 사진 포함 백업 왕복, 동시 백업·입력, 재실행 유지, 손상·참조 오류·경로 이탈 입력 거부를 자동 테스트했습니다.

DB 삽입 또는 예측 재계산 실패를 주입해 기존 기록·사진·화면 상태가 유지되는지도 검사했습니다. 화면 테스트에서는 수정·삭제와 백업 저장·복원 확인·취소를 검증합니다. Android 파일 선택·저장 코드는 APK 빌드로 확인했으며 실제 USB 파일 선택과 권한 동작은 갤럭시탭에서 검증해야 합니다.

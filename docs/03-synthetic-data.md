# 합성 데이터 설계

## 제작 원칙

식별자·날짜·운용 수치·정비 서술·금액은 생성한 가상 값입니다. 실제 행을 복사하거나 실제 기록의 빈 값을 추정해 학습 표본으로 쓰지 않았습니다. 생성기는 원본 문서를 열지 않습니다.

일반적인 차량 운용·정비 항목을 사용하며 부속 범주는 실제 부품 카탈로그나 가격을 보증하지 않습니다. 원본 구조 분석과 집계 정보는 공개하지 않습니다.

## v3 규모

| 종류 | 건수 | 용도 |
| --- | ---: | --- |
| 가상 차량 | 500 | 차량 분할과 이력 연결 |
| 월별 운용 | 24,500 | 월간·누적 거리, 시간, 유류량 |
| 정비 | 5,746 | 예방정비와 가상 고장수리 |
| 예측 표본 | 24,000 | 월말 관측 → 다음 달 고장수리 |
| 문장 분류 | 5,746 | 계통과 예방/고장수리 구분 |

앱에는 차량 100대, 최근 24개월 운용 2,400건, 정비 583건만 포함합니다. 전체 학습 파일은 태블릿에 자동 복사하지 않습니다.

## 6가지 시나리오

| 시나리오 | 방식 |
| --- | --- |
| 정기 예방정비 | 짧은 정비 주기로 가상 마모 누적 감소 |
| 정비 지연 | 긴 간격으로 상태 악화 가능성 증가 |
| 운행량 증가 | 운행량이 월별로 증가하고 다음 달로 이어짐 |
| 반복 수리 | 같은 부속의 재발, 작은 상태 회복 폭 |
| 저운행 | 낮은 운행량, 완만한 변화와 드문 사건 |
| 고운행 | 높은 운행량에 따른 변화와 수리 가능성 |

가상 마모는 운행에 따라 증가하고 정비 후 감소합니다. 월별 유류량에 상태 변화와 작은 변동을 반영했습니다. 확률성을 남겨 우발성 사건도 발생할 수 있습니다.

계수와 관계는 시연용 가정이며 실제 연비로 고장을 진단하는 방법이나 검증된 차량 물리 모델이 아닙니다.

## 입력과 정답

예측에는 다음 14개 특성만 사용합니다.

- 출고연도·차령.
- 누적 거리·시간·유류량.
- 월간 거리·시간·유류량 및 L/100km.
- 정비 이력 유무·마지막 정비 이후 일수.
- 최근 90일 정비 건수·고장수리 건수·비용 합계.

내부 마모, 시나리오 이름, 사건 확률, 화면 위험도, 식별자와 미래 정답은 특성에서 제외합니다. 이력 없는 경우 경과일은 -1입니다.

정답은 **다음 달의 가상 고장수리 기록 발생 여부**입니다. 고장 확정, 파손, 잔여수명과 다르며 예방정비를 양성으로 세지 않습니다.

## 분할과 미래 정보 제외

차량은 학습 350대·검증 75대·시험 75대로 분리합니다. 예측 파일 전체 행은 16,800/3,600/3,600건입니다. 실제 숫자 학습·검증에서는 정답 기간이 미래 평가 연도 이전에 끝나는 행만 선택합니다. 미래 시험 675건은 미학습 차량에서 따로 평가합니다.

문장 분류는 4,007/878/861건입니다. 차량·템플릿 종류를 분할 간 분리했지만 유한한 부속명과 같은 분할 안의 문장 반복은 남아 있습니다.

정규화·어휘는 학습 자료로만 구성하고 검증 자료로 후보·임계값을 선택합니다. 시험 점수를 보고 모델을 다시 고르지 않았습니다.

## 무결성

파일 해시, 고유 ID, 차량 참조, 누적값 증가, 시간 순서, 정비 집계, 전체 입력 특성과 미래 정답을 재계산했습니다. 차량·템플릿 분리와 앱 초기 건수도 검사했습니다.

동일 시드 재생성 결과가 저장된 데이터 및 앱 초기 데이터와 일치했습니다. 사용자 기록·사진은 학습에 자동 편입하거나 전송하지 않습니다.

## 저장·오프라인 재실행 근거

- 가상 차량: `QA-TABLET-1103`, 차종 `QA_TEST_VEHICLE`, 2020년, 20,000km / 500H / 1,000L.
- 가상 정비: `QA_FILTER`, 설명 `QA_tablet_smoke_test_only`, 비용 1,000원, 교환 여부 미확인, 정비 구분 미분류. 날짜는 기기 시간대의 `2026-11-04`다. QA 수행일 표기는 사용자 채팅 시간대인 2026-11-03을 따른다.
- 저장 완료 UI에서 차량·부품명·미확인 교환 상태 안내를 확인했다.
- 비행기 모드를 켜도 Wi-Fi가 남아 있어 Wi-Fi도 명시적으로 껐다. `airplane_mode_on=1`, `wifi_on=0`과 라우팅에서 Wi-Fi·모바일 외부 경로가 없음을 확인한 뒤 앱을 강제 종료하고 cold start했다. 패킷 캡처는 하지 않았다.
- 오프라인 홈의 등록 차량 1대, 차량 목록의 정비 1회·최근 정비일, 상세의 1,000원 비용을 확인했다.
- 재시작 후 DB에서 위 차량·정비 입력값이 동일하고 `integrity_check=ok`, 외래키 위반 없음도 확인했다.
- 테스트 차량 1대와 정비 1건은 검토할 수 있도록 앱에 남겨 두었다. 실제 업무 기록으로 사용하지 않는다.

## 실기기에서 추가로 관측한 문제

### TQA-01 · P2 · 자정 경과 후 상단 날짜가 갱신되지 않음

태블릿 시계가 11월 4일 00:01을 표시할 때 앱 헤더는 `2026.11.03`을 유지했다(`08-required.png`). 앱을 다시 실행한 뒤에는 `2026.11.04`로 갱신됐다(`12-current.png`). `lib/data/clock.dart`의 `currentTimeProvider`는 생성 시 `DateTime.now()`를 한 번 반환하고 날짜 변경을 스스로 통지하지 않는다. 정비 입력도 같은 provider를 사용하므로 기본 날짜의 영향 범위를 별도 회귀 검사해야 한다. 이번에는 헤더의 정체와 재시작 후 갱신을 직접 확인했으며, 잘못된 날짜의 정비 저장까지 재현한 것은 아니다.

### TQA-02 · P2 · 카메라 권한 거부 직후 요청이 다시 표시됨

첫 권한 거부 후 뒤쪽 화면은 이미 ‘카메라 사용 불가 · 수동 부품 선택’을 표시했으나 동일 Android 권한 창이 한 번 더 나타났다(`29-permission.xml`, `30-camera-denied.png`). 두 번째 거부 후 수동 선택 화면으로 진행했고, ‘선택 부품의 근거·이력 확인’에서 같은 QA 차량과 외관 선택을 유지한 정비지원으로 이동했다(`31-fallback.xml`, `32-manual-support.xml`).

`lib/ui/vision.dart`는 `resumed` 상태이며 촬영 단계일 때 `startCamera()`를 자동 호출한다. 권한 창 복귀와 자동 재시도의 상호작용 가능성을 검토해야 한다. 이번 기기에서 1회 흐름을 관측한 결과로, 모든 Android 버전의 반복 재현을 확인한 것은 아니다. 권한 거부 후에는 명시적인 재시도 동작 전까지 재요청하지 않는지 검증이 필요하다.

## 임시 설정 복원

USB 연결 중 화면 유지 값을 0에서 2로 잠시 변경했다가 0으로 복원했다. 자동 회전은 기존 `accelerometer_rotation=1`, `user_rotation=0`으로 복원했다. 비행기 모드 0, Wi-Fi 1, 모바일 데이터 1도 검사 전 값으로 복원했다. 카메라는 권한을 부여하지 않았고, 거부 시험에서 생성된 `user-set`·`user-fixed` 플래그를 지워 다음 실제 촬영 시 다시 물어보는 상태로 돌렸다. 앱 전체 데이터는 지우지 않았다.

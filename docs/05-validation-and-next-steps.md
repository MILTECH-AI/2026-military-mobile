## 미검증 범위

갤럭시탭 미연결 상태여서 실기기 성능, 비행기 모드, 카메라 권한·촬영·저장, 실제 터치, 장시간 사용과 기기별 차이는 미검증입니다. 실제 기록에서의 모델 정확도도 검증되지 않았습니다.

2026-10-31 결정: Galaxy Tab S10 FE는 확보했으며 시연용 기기입니다. 연결은 사용자 요청으로 나중에 진행하고 PC 작업을 우선합니다. 지원 대상은 여러 기종이며 저사양 기본 단계에서도 핵심 업무를 수행하는 것이 목표입니다. RAM·지연·저장공간의 최소 수치는 실측 후 확정하며 지금은 숫자를 지정하지 않습니다. PC 스레드 제한과 에뮬레이터 결과는 실기기 결과와 구분합니다.

독립 라벨링·일치도 평가는 중단했습니다. 배포본과 절차는 private에서 보관만 하고 매핑 정확도는 주장하지 않습니다. 정비 문장 계통 분류 파일럿은 단일 검토자 초안으로 진행할 수 있으나 자료 작성 경위 미확인 및 단일 검토자 라벨이라는 한계를 기록해야 합니다. 앱의 반입 개념 연결은 후보 제시·사용자 확인으로 변경했습니다. 이전 자동 연결은 확인시각이 없으므로 미확인 후보로 취급합니다.

### Android 최소 지원 사양 제안

앱 전체 `minSdk=24`는 이번 단계에서 유지합니다. 우선 CPU 실행 경로를 검증하고, LLM을 선택 기능으로 분리해 LLM의 더 높은 조건 때문에 앱 전체 최소 버전을 올리지 않는 방향입니다. 64비트 ARM을 우선 검증하고 32비트 지원은 해당 모델·런타임 ABI 포함 여부를 따로 확인합니다. 이는 최소 지원 성능을 측정해 확정한 결과가 아닙니다.

| 후보 | 직접 확인한 공식 근거 | 판단과 미확인 범위 |
| --- | --- | --- |
| ONNX Runtime CPU | 실제 반입한 [1.23.2 공식 AAR](https://repo.maven.apache.org/maven2/com/microsoft/onnxruntime/onnxruntime-android/1.23.2/onnxruntime-android-1.23.2.aar)의 매니페스트에서 최소 API 24, JNI에서 ARM·x86 ABI를 직접 확인 | 앱 minSdk 24 유지. 실제 임베딩은 API 24 x86_64 에뮬레이터에서 실행 확인. ARM 실기기·최소 RAM·NNAPI 성능은 이 결과로 확정하지 않음 |
| LiteRT | [버전별 Android 표](https://developers.google.com/edge/litert/android)는 Interpreter 1.4.2 최소 API 21, CompiledModel 2.0.3 최소 26을 기재. 2.3.0 안내도 있으므로 표의 다른 버전 조건을 그대로 옮기지 않음 | 버전을 고정한 CPU 번들 경로를 선택하고 실제 AAR 병합 매니페스트 확인 필요. Google Play 서비스 동적 런타임은 폐쇄망 경로로 사용하지 않음 |
| llama.cpp | [공식 Android 빌드 안내](https://github.com/ggml-org/llama.cpp/blob/master/docs/android.md)의 NDK 예제는 API 28. 현재 [Android 라이브러리 예제](https://github.com/ggml-org/llama.cpp/blob/master/examples/llama.android/lib/build.gradle.kts)는 minSdk 33 및 arm64-v8a/x86_64 | 예제 33이 코어 라이브러리 전체의 최소라고 단정하지 않음. 현재 예제 그대로의 도입은 API 24에 맞지 않음. 선택적 자체 JNI 경로의 API 28 빌드·실행을 별도 검증하고 미지원 기기에서는 원문 검색 유지 |

1단계 자동 검증은 기기 사양 채널 대역, 선택 정책, 직렬 요청, 부분 로드 실패, 추론 시간 초과, 해제 실패와 종료 미확인 격리, LLM 미설치 대체를 대상으로 합니다. 이후 실제 ONNX 어댑터를 연결해 API 24·RAM 3GB 설정·가상 2코어 x86_64 에뮬레이터 시험을 수행했습니다. 프로세스 분리, 실제 모델 로드·질문 임베딩·혼합 검색·해제, 적용조건 차단, 지원하지 않는 모델 ID의 네이티브 로드 실패에 따른 키워드 복귀·프로세스 복구를 확인했습니다. 카메라 차단 수동 흐름은 Flutter 대역 테스트이며 실제 MDM 정책 시험과 구분합니다. 실제 OOM·실기기 성능·순간 최대 메모리는 여전히 미검증입니다. 실행기의 30초 watchdog은 안전장치의 임시 제한이며 실측한 사용자 응답시간 기준이 아닙니다.

현재 사용하는 ONNX Android 1.23.2 AAR은 내려받은 매니페스트에서 최소 API 24를 직접 확인했습니다. PC도 같은 런타임 버전입니다. CPU 스레드 제한 PC 값과 에뮬레이터 값은 별도로 기록하며 기종별 모델 단계의 확정 근거로 사용하지 않습니다. 계측 결과·모델 해시·입력 길이·네트워크 상태·검색 순위는 private에 보관합니다. 128토큰 입력에서는 토큰 ID가 같아도 벡터 차이가 관측됐고, 실험용 최대 절대 오차 0.001 검사 기준을 넘었습니다. 이는 합의된 운영 품질 기준이 아니며 검사 실패를 숨기지 않고 기능 시험과 분리합니다. 양자화 표현·최적화 옵션 비교에서도 차이가 남아 정확한 내부 원인은 미확정입니다. 관측상 더 나았던 원래 U8S8·ALL 설정을 명시하고, 모델 해시 외에 실행 설정이 다른 색인을 거부합니다. 수치 정합성·현재 순위 결합의 관련성 평가가 완료됐다고 주장하지 않습니다.

### 임베딩 비교 기준 변경 및 교환주기 역할 분리

사용자 승인에 따라 원소별 최대 절대 오차는 진단값으로 남기고, 토큰 ID 완전 일치 → 질문 벡터 간 코사인 유사도 → 동일 색인·동일 질문·동일 선택 조건의 상위 1·3·5개 순서 비교로 검증합니다. 앱이 표시하는 근거 단위의 순수 벡터 정렬과 최종 혼합 정렬을 각각 비교하고, 조각 단위 정렬도 별도 기록합니다. 모델·실행 설정뿐 아니라 전체 색인과 질문이 같은지도 검사합니다. PC와 Android는 같은 Dart 정렬 함수를 사용합니다. 이전 원소 오차 검사 실패는 역사적 결과로 보존합니다.

기준 변경 이유: 현재 검색은 코사인 유사도로 순서를 정하므로 좌표 하나의 오차만으로 실제 검색 결과의 변화를 판단할 수 없습니다. [Sentence Transformers 공식 문서](https://www.sbert.net/docs/sentence_transformer/usage/semantic_textual_similarity.html)도 기본 유사도로 코사인을 사용합니다. 코사인이 높아도 근접 점수의 순서가 바뀔 수 있으므로 순위 비교를 생략하지 않습니다. [ONNX Runtime 양자화 안내](https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html)의 수치 차이 설명은 참고이며 이번 플랫폼 간 차이의 내부 원인을 입증한 것으로 해석하지 않습니다. 이 기준은 이번 호환성 표본의 판정 기준이고 검색 관련성·확대 범위의 정확도 보장이 아닙니다.

교환 수치와 잔여거리·기간 판정은 `MaintenanceRule`이 참조하는 검증된 주기와 기준시각의 부대 선택에서만 가져옵니다. 질문이나 검색 원문에서 수치를 읽어 판정값을 바꾸지 않습니다. RAG는 원문과 위치를 반환하고 인용 숫자가 적용 주기와 다를 수 있음을 표시합니다. 반입된 조각에는 원문 위치가 주기 프로필과 일치할 때만 일반·가혹 및 거리·기간 메타데이터를 부여합니다. 동일 표에 두 축이 함께 있으면 둘 다 보존하며 알 수 없는 필드를 채우지 않습니다. 조건 메타데이터의 변조는 키워드 대체 경로로 처리합니다.

정렬 우선순위는 차량·부품·기준시각 적용조건 → 질문의 절차/주기 의도 → 명시 조건(없으면 부대 선택) → 거리·기간 축 → 기존 키워드/벡터 순위 결합입니다. 명시 질문은 검색 우선순위만 바꾸고 부대 설정은 바꾸지 않습니다. 두 기준 비교는 양쪽을 유지하고 부정·모호한 조건은 한쪽으로 추측하지 않습니다. 현재 조건 해석은 규칙 기반이므로 팀 작성 평가에서 누락·오해를 확인해야 합니다.

`test/rag_conditions_test.dart`는 일반 원문의 벡터 점수가 높은 가혹 기간 질문, 질문과 부대 선택의 충돌, 미선택, 기준 비교, 절차, 거리·기간 축, 원문 숫자의 판정값 비영향, 순위 차이 검출을 검사합니다. `test/local_rag_test.dart`는 조건 메타데이터 불일치를 검사합니다. 검색 품질용 25문항은 질문·정답을 비워 둔 로컬 HTML/JSON 양식이며 `tools/prepare_rag_question_form.py`가 private에 생성합니다. 호환성 입력과 구분하고 미검토 문항은 평가에서 제외합니다. 독립 라벨링·일치도 평가는 재개하지 않습니다.

실기기 재측정은 `tools/run_embedding_probe.ps1 -Serial <승인된 기기>`로 동일 묶음·입력·PC 순위를 반입해 실행합니다. 이 스크립트는 테스트 APK를 설치하며 기존 앱 데이터를 초기화하지 않습니다. 기기 정보·비행기 모드 상태·결과를 private에 기록합니다. API 24만 허용하던 시험 진입 조건은 제거했으며 플랫폼 구분은 기기 정보와 함께 기록합니다. 현재 앱의 실제 측정 결과와 기종별 최소 사양은 구분해야 합니다.

이번 재측정은 API 24·RAM 3GB 설정·가상 2코어 x86_64 에뮬레이터입니다. 14개 입력의 토큰 ID가 전부 일치했고, 각 입력의 미선택·일반·가혹 42개 조합에서 조각/근거/혼합 정렬의 상위 1·3·5개 순서가 모두 일치했습니다. 이는 같은 정렬 함수로 PC 기준 벡터와 실제 Android 벡터를 비교한 것이며 42번의 화면 전체 시험을 뜻하지 않습니다. 별도로 실제 RAG 로드·검색·해제와 세 질문의 조건 정렬, 적용조건 차단, 로드 실패 대체·복구도 통과했습니다. 비행기 모드와 가상 무선 링크 차단 후 재시험했고 전후 라우팅 경로는 비어 있었습니다. 패킷 캡처는 하지 않았습니다.

코사인 최솟값은 0.9998520523542527입니다. 기존 128토큰 입력의 최대 좌표 차이 0.001039999461199999는 재현됐고, 추가한 17토큰 입력에서는 0.002624011873636249가 관측됐습니다. 이후 사용자가 0.001은 예시였음을 명시하고 순위 일치 기준을 승인했습니다. 좌표 차이는 판정 차단 조건이 아니며 내부 수치 차이 원인은 미확정입니다. 원소 오차의 과거 실패 이력과 새 원시값은 함께 보관합니다. 상세 결과는 `private/retrieval-stage/result.json`, 승인 기록은 같은 경로의 `user-acceptance.json`입니다. 당시 Flutter 테스트 106개가 통과했고 후속 LLM·Vision 단계의 현재 전체 테스트는 118개입니다. 실기기·검색 관련성 평가는 남아 있습니다.

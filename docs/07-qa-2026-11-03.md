현재 판정은 **전체 정상 동작 확인 미완료**다. Flutter 전체 자동 테스트 126개 중 100개가 통과하고 26개가 실패했다. 실제 날짜 계산 오류 1건, 화면 기준 이미지 비교 실패 22건, 테스트 준비물·출력 폴더 누락 3건을 구분했다. 실기기와 APK 검사는 완료하지 않았다. 앱 코드와 화면 기준 이미지는 변경하지 않았다.

후속 진행: 같은 날 Android 환경을 구성해 APK 빌드·권한 검사·태블릿 설치·초기 DB 검증을 완료했다. APK 권한 테스트 2개도 재실행해 통과했다. 이후 태블릿에서 가상 차량·정비 저장, 오프라인 cold start·기록 유지, 가로/세로 배치 및 카메라 거부 후 수동 경로를 확인했다. 자정 날짜 갱신과 카메라 권한 재요청 문제도 추가 관측했다. 위 100/26은 최초 실행 결과이며 자세한 결과는 [태블릿 검증 기록](08-tablet-qa-2026-11-03.md)을 따른다.

## 확인한 문제

### QA-01 · P2 · 서머타임 전환을 지나는 정비 예정일이 하루 앞당겨짐

- 위치: `lib/data/maintenance_support.dart:571`의 `now.add(Duration(days: ...))`.
- 재현: `test/maintenance_support_test.dart`의 ‘운용 추세가 충분할 때만 다음 정비 날짜를 추정한다’.
- 기대: `2026-12-03 00:00:00`. LA 시간대 실제 결과: `2026-12-02 23:00:00`.
- 원인: 달력 날짜를 더해야 하는 곳에서 하루를 24시간으로 계산한다. 서머타임 종료를 지나면 현지 시간이 한 시간 이동해 날짜 표시도 전날이 된다.
- 동일 테스트는 `TZ=Asia/Seoul`에서 통과했다. 한국 시간대에서 이번 실패는 재현되지 않았다.
- 조치: 달력 날짜 연산으로 변경하고 서머타임 시작·종료를 가로지르는 회귀 검사를 추가해야 한다. 인접한 관측일 수·최근 30일 판정도 날짜 기준과 경과시간 기준을 명확히 구분해야 한다.

### QA-02 · P2 · 새 복제본에서 모델 테스트 2개가 로컬 산출물에 의존

- `test/local_models_test.dart:68`: Git에서 제외된 `output/models/parity_fixtures.json`을 필수 입력으로 읽어 실패한다.
- `test/local_models_test.dart:268`: 부모 폴더를 생성하지 않고 `output/models/live_update_report.json`을 써서 실패한다.
- 추가 확인: `output/models/`를 만든 뒤 저장·예측·재실행 테스트만 다시 실행하면 통과했다. 이 실패는 출력 폴더 누락으로 분리됐다. 동일 추가 실행에서 LA 시간대 날짜 오류는 다시 재현됐다. 전체 100/26 수치는 폴더 생성 전 최초 실행 결과를 보존한 것이다.
- 패리티 fixture는 `tools/train_local_models.py`에서 생성하지만, 이 도구는 모델 파일도 다시 학습·저장한다. 단순 QA를 위해 실행하면 검증 대상 모델이 달라질 수 있어 이번에는 실행하지 않았다.
- 같은 테스트의 보고서 환경값도 `Windows Flutter test runner`로 고정되어 있어 macOS 실행 결과를 잘못 표시한다(`test/local_models_test.dart:249`).
- 조치: 합성 고정 fixture를 테스트 자원으로 관리하거나, 기존 모델을 변경하지 않는 fixture 생성 절차를 제공한다. 출력 전 부모 폴더를 생성하고 실제 운영체제를 기록한다.

### QA-03 · 판정 보류 · 화면 기준 이미지 비교 22개 실패

- 홈·정비지원·차량 등록·기록·대형 글자 등의 화면 비교에서 픽셀 차이가 발생했다.
- 비교 샘플의 홈 화면은 배치와 표시 문구가 유지되었고 차이가 주로 글자·아이콘 경계에 분포했다. macOS와 기존 기준 이미지 생성 환경의 렌더링 차이 가능성이 있으나, 모든 차이를 환경 문제라고 확정하지 않았다.
- 자동 테스트의 기준 이미지는 갱신하지 않았다. 이미지 비교에서 중단된 테스트는 그 뒤의 사용자 동작까지 통과했다고 해석하면 안 된다.
- 조치: 기준 이미지 생성 OS·SDK·폰트 조건을 고정해 재실행하고, 다르면 플랫폼별 기준 또는 검토된 비교 방식을 적용한다.

### QA-04 · 실행 차단 · 최종 Android APK·실기기 검증 필요

- `test/apk_permissions_test.dart:14`는 먼저 빌드된 debug APK를 요구한다. 이번 작업 폴더에는 APK가 없어 실패했다.
- JDK·Android SDK·ONNX Runtime AAR이 없고, 소스에는 `android/gradlew` 및 wrapper JAR도 포함되지 않았다. Flutter 빌드 과정에서 생성·준비 가능한 항목과 외부 설치 항목을 구분해 빌드를 재현해야 한다.
- 소스 manifest에는 CAMERA 권한과 `allowBackup=false`가 있지만, 의존성을 병합한 **최종 APK**에서 검증한 결과는 아니다.
- 조치: Android 빌드 후 APK 권한 검사 → 태블릿 설치 → 비행기 모드·저장 후 재실행·카메라 허용/거부·사진 포함 백업 왕복·실제 ARM64 모델 실행 순으로 확인한다.
